# 首页仪表盘 UI 结构说明

> 状态：已实现。  
> `GET /` 为首页仪表盘，`GET /workbench/<project_id>` 为工作台；项目不存在时重定向首页并提示。  
> 现有五阶段工作台、RAG、文件上传和导出模块未重写。

## 1. 页面层级

```text
Dashboard Page
├── Top Bar
│   ├── Brand / Product Name
│   ├── "新建项目" Primary Button（固定可见）
│   └── 运行模式 Badge（沿用本地演示/DeepSeek 在线）
├── Dashboard Content
│   ├── Hero / 简要说明
│   ├── Stats Grid（4 张统计卡片）
│   │   ├── 项目总数
│   │   ├── 进行中项目
│   │   ├── 已归档阶段
│   │   └── 最近 7 天活跃
│   └── Project Section
│       ├── Section Header（项目列表 / 共 N 个）
│       ├── Project Grid（桌面多列 / 移动单列）
│       │   └── Project Card × N
│       └── Empty / Loading / Error State
└── New Project Modal（复用现有项目表单）
```

## 2. 顶部导航

- 左侧品牌沿用当前工作台样式。
- 右侧固定放“新建项目”主按钮；滚动项目列表时仍然可见。
- 不在首页显示阶段导航，避免用户误以为首页属于某个项目。
- 项目卡片点击后进入工作台。

## 3. 统计卡片

4 列布局，复用现有 CSS 变量：

| 卡片 | 数据字段 | 视觉 |
| --- | --- | --- |
| 项目总数 | `stats.total_projects` | 深色数字 + 小图标 |
| 进行中项目 | `stats.active_projects` | 青色强调 |
| 已归档阶段 | `stats.archived_stages` | 绿色强调 |
| 最近 7 天活跃 | `stats.active_last_7d` | 琥珀色强调 |

- 统计卡片加载中显示骨架屏（固定高度），而不是先显示 0。
- 接口失败显示“统计暂不可用”，不阻塞项目列表。
- 数值使用千分位格式化；0 是合法值，但只在数据加载完成后显示。

## 4. 项目卡片

每张卡片结构：

```text
Project Card
├── Header
│   ├── 客户名称（主标题，最多两行）
│   └── 当前阶段 Badge
├── Meta
│   ├── 行业
│   └── 生产模式
├── Stage Dots（五阶段状态圆点）
│   ├── 阶段 01 调研
│   ├── 阶段 02 数据
│   ├── 阶段 03 方案
│   ├── 阶段 04 配置
│   └── 阶段 05 上线
├── Summary
│   └── last_summary（最多 50 字，无内容时显示“暂无对话摘要”）
└── Footer
    └── 最近更新：last_active_at
```

### 阶段状态颜色

- `not_started`：灰色圆点 / 浅灰标签。
- `in_progress`：琥珀色圆点 / 浅琥珀标签。
- `archived`：绿色圆点 / 浅绿色标签。

颜色直接复用工作台 `.stage-state--*` 的视觉语义，不新增另一套状态色。

### 卡片交互

- 整卡可点击，进入 `/workbench/<project_id>`。
- Hover 抬升 1–2px，边框变青色，出现轻量阴影。
- 键盘可聚焦，Enter/Space 触发进入。
- 卡内不放大段操作按钮，避免误触；新建项目统一走顶部按钮。
- 移动端卡片单列，阶段圆点允许换行。

## 5. 项目卡片管理

- 卡片右上角 `⋯` 菜单：重命名、删除。
- 重命名：客户名称、行业轻量弹窗；成功后替换卡片。
- 删除：固定文案确认；成功后从列表移除并重算统计。
- 删除失败保留卡片并 Toast 显示具体原因。

## 6. 列表排序与数据

- 数据全部来自 `GET /api/dashboard`。
- 后端已按 `last_active_at` 倒序返回；前端不二次改变业务排序。
- 项目卡片字段严格使用：
  - `project_id`
  - `client_name`
  - `industry`
  - `production_mode`
  - `current_stage`
  - `stage_status`
  - `last_active_at`
  - `last_summary`

阶段键与工作台阶段映射：

| API 键 | 工作台阶段 |
| --- | --- |
| `stage1_research` | 阶段一 现状调研 |
| `stage2_data` | 阶段二 数据梳理 |
| `stage3_solution` | 阶段三 方案设计 |
| `stage4_config` | 阶段四 配置验证 |
| `stage5_golive` | 阶段五 上线验收 |

## 6. 加载 / 空 / 错误状态

### 加载

- 首屏先渲染统计骨架卡和项目卡骨架。
- 加载完成前不显示“0 个项目”的空状态。
- 刷新项目列表时保留旧列表并显示顶部轻量加载条，避免页面跳动。

### 空状态

- 无项目时显示：
  - 插画/机器人图形
  - “还没有 APS 实施项目”
  - “从一次结构化调研开始，创建第一个项目。”
  - 主按钮“新建项目”
- 空状态只在接口成功返回且 `total_projects === 0` 时显示。

### 错误状态

- 显示“仪表盘加载失败”和“重试”按钮。
- 错误信息使用现有 Toast + 页面内提示，不影响新建项目入口。

## 7. 新建项目

复用现有客户信息表单字段：

- 客户名称
- 行业
- 生产模式
- 核心痛点

创建成功后：

1. 使用 `POST /api/project` 返回的 `project_id`。
2. 跳转 `/workbench/<project_id>`。
3. 工作台加载项目上下文并进入阶段一。

## 8. 返回首页（已实现）

- 工作台顶部左侧增加“← 返回首页”。
- 五个阶段都保留该入口。
- 返回前检查当前阶段是否存在未归档内容：
  - 当前阶段有最新 Agent 输出但尚未归档；
  - 或阶段状态不是 `archived` 且有对话/输出。
- 有未归档内容时弹出轻量确认框：
  - 文案：“当前阶段有未归档内容，确定离开？”
  - “取消”留在工作台。
  - “确认”跳转 `/`。
- 确认框使用页面内浮层，不阻断其他区域滚动或操作。
- 当前阶段已归档或无内容时直接返回首页。

## 9. 响应式

- 桌面 ≥1280px：统计 4 列，项目 3 列。
- 平板 768–1279px：统计 2 列，项目 2 列。
- 移动 <768px：统计 2 列或单列，项目 1 列。
- 项目卡片操作区在移动端保持整卡可点击，不引入额外悬浮按钮。

## 10. 不改动范围

- 不重写五阶段工作台结构和阶段切换逻辑。
- 不重写 RAG 检索、文件解析、上传和来源展示。
- 不重写导出功能。
- 不新增独立消息列表页。
